# UH05: bounded native fiat admission guard

Fresh Kraken groups previously admitted native foreign fiat through a manually created EUR-base crypto position with a matching ticker. Fresh groups now require native fiat rows to use the existing EUR cash path; cash bindings also require the native fiat source role. Foreign fiat remains unsupported.

The check runs while reconstructing actions in the existing importer. Existing group presence is computed internally before reconstruction and cannot be supplied through public options. It permits reconstruction only: all existing complete origin, payload, membership, binding, ownership and journal checks must still pass before a group is recognized as an unchanged duplicate. No existing group enters the fresh booking path through this exception. Position resolution used by chronology and documentary withdrawal is unchanged.

The two synthetic legacy fixtures were produced by the actual unchanged v297 importer, commit `602ef464a94381ba86615f8e25f82a71c2d25e8d`, importer blob `82f7e7cca5094ce0ad33ba8f8701c513d6b18d50`. They are preserved rather than regenerated with the guarded code. Original private source rows, references and amounts are excluded from this repository.

Seven unit groups cover supported fresh foreign-fiat event classes, EUR/cash native roles, legitimate EUR/crypto/stablecoin/internal-fee quantities, actual old-model backup/replay/Undo/terminal withdrawal, altered/incomplete/remapped/orphaned legacy groups, mixed valid/invalid shared import without partial commit, and stale shared confirmation plans. Caller-supplied reconstruction options cannot grant the internal exception. The six inherited test groups reproduced five expected protection failures on unchanged v297 before the change; all now pass. The full suite has 1,326 tests, no failures or skips, and syntax passes.

The new actual shared-UI contract tests synthetic fiat exchange with internal fee credits, fiat reward, a valid EUR sibling beside blocked foreign fiat, and cash without a native fiat role in Chromium, Firefox and WebKit. It requires the visible specific reason, disabled provider/global approvals and save, rejection through the submit handler even after a scripted submit, byte- and revision-identical canonical IDB records, offline reload nonmutation, four responsive widths and full existing Axe tags. It is appended to the existing shared-import gate, so every existing integration and production path retains it. Existing quota, post-put, Undo, restore and real second-tab race checks remain unchanged.

Only runtime files `src/kraken-import.js` and `sw.js` change. No journal/storage schema, identity key, financial engine, migration, historical correction, FX rates, costs or tax assumptions are added. Cache candidate: `foliolab-open-v298`. This document records local candidate qualification, not integration, deployment or LIVE_ACCEPTED. Those remain mandatory.

UH05 remains PARTIAL. DKB stays outside; external financing is not gain; internal principal is neither income nor a new cost basis. Wallet/staking gaps and historical Alpha-IDB cause remain UNKNOWN.
