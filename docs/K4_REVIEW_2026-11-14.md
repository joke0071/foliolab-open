## Verfolgte Restore-Pfade und Fehlergrenzen

Datei: backupFile-change → Dateigröße/JSON → optional echte v2-Entschlüsselung → optional vollständiges Paket entpacken → safeImport → Bestätigung → optionale Konfigurationsentscheidung → model/imported → save → PortfolioStorage.save → backup → atomic-storage.portablePortfolio (nochmals safeImport/backup) → revisioniertes CAS/tx.oncomplete. Danach Passwortübernahme, Status und Einstellungen/UI. Datei unterstützt zusätzlich direktes unverschlüsseltes Portfolio-JSON; unverschlüsselte vollständige Konfigurationspakete sind verboten.

Drive: ausgewählter echter Button → OAuth/HTTP-Transport → Größenprüfung/v2-Paket/Passwort → Entschlüsselung/Entpacken → validateData=safeImport → Bestätigung → restoreData führt erneut safeImport aus → angebotene Rückfallsicherung → Konfigurationsentscheidung → derselbe save-/Storagepfad. Anschließend übernimmt das Drive-Modul den Passwortvault und meldet das Gesamtergebnis. Drive akzeptiert hier nur v2-passwortverschlüsselte Pakete. Der zusätzliche Import macht idempotente Normalisierung besonders relevant.

Beide Wege lassen bei Typ-/Dezimalablehnung vor CAS den alten kanonischen Record erhalten. Bei konkurrierendem CAS bleibt der Gewinner gespeichert und wird von save neu geladen; die neue Identitätsbedingung erhält dieses Modell auch sichtbar. Ein erfolgreich aufgelöster save bleibt trotz späterer Renderfehler ein Commit. Der Drive-Callback markiert Nachbereitungsfehler mit restoreCommitted, das Drive-Modul trennt Portfolio/Passwort/Abschluss. Die Datei setzt ihre eigene Grenze nach save bzw. Recovery. Fehler beim tatsächlich nicht mehr funktionsfähigen Browser/DOM sind keine universell garantierte sichtbare Meldung.

Recovery bei beschädigtem Speicher ist ein eigener Zweig: Originaldownload erforderlich, recoverFromBackup prüft die ursprünglichen Bytes. Dessen separate lokale Verträge wurden ausgeführt; die sieben nativen Paare belegen reguläres Restore und keine native Korrupt-Recovery/OS-Abbruchgarantie. Ungespeicherte Einstellungen werden durch den regulären Restore ohne angenommene Konfiguration nicht zum gespeicherten Entwurf gemacht.
